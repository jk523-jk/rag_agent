# 代码导读：每个模块怎么实现、在哪个文件

> 面向「我要改某个功能，该打开哪个文件」。全部内容对照当前代码（2026-10-18）核对过，不含臆测。

---

## 0. 全景

```
Vue 前端 (frontend/src)
   │  /api/chat/stream (SSE) · /api/data/*
   ▼
API 层 (backend/app/api)          chat.py · data.py · health.py
   ▼
控制类拦截 (core/guard.py)  ── 命中即拒绝，不进 Agent
   ▼
Agent 编排 (agent/graph.py)  create_agent + 10 条硬规则 + 限流中间件
   ▼                    └── 模型自己选工具（工具描述即路由）
工具层 (tools/*)  9 个只读工具
   ├── RAG (rag/*)  ── Chroma 向量库 (corpus/chroma)
   └── 数据层 (db/*) ── MySQL 8（只读账号 + 3 层护栏）
```

一句话：**模型只负责「选哪个工具、把结果讲成人话」，所有数字与判定都来自 SQL 和检索结果。**

## 1. 后端模块

### 1.1 应用入口 `backend/app/main.py`（60 行）

`lifespan` 里按顺序做四件事：

1. `setup_logging()` 初始化日志
2. `await init_pool()` 建 MySQL 连接池——**失败不抛异常**，让服务照常起来，状态交给 `/api/health` 暴露
3. `build_agent()` 装配 Agent（单例，只建一次）
4. `start_session_reaper()` 启动会话过期清理任务

退出时反向收尾：停止清理任务、关闭连接池。三个 router 统一挂在 `/api` 前缀下。

> 为什么连接失败也让服务起来：容器反复重启时运维看不到原因，改为起服务 + `curl /api/health` 直接读错误类别。

### 1.2 配置 `backend/app/core/config.py`（166 行）

pydantic-settings，`env_file=".env"`（**相对当前工作目录**，这是「必须在 `lab-hazmat-agent/` 下启动」的根因）。所有字段都有默认值，缺 `.env` 也能起。

三个值得看的实现：

| 成员 | 作用 |
|---|---|
| `mysql_ssl_args` | 把 `MYSQL_SSL` / `MYSQL_SSL_CA` 翻译成 aiomysql 的 `ssl` 参数 |
| `chroma_path` | 相对路径按**项目根**解析（不是 CWD）。否则从别的目录启动会静默连到一个空向量库，表现为"检索永远为空" |
| `resolve_ddl_paths()` | 扫描 `mysql/init` 下所有**内容含 `CREATE TABLE`** 的 `.sql`，而不是硬编码 `01_schema.sql`。这是修过的坑：设备表定义在 `05_equipment.sql`，原实现没读它，模型根本不知道有 equipment 表 |

`get_settings()` 带 `lru_cache`，全项目共用一份配置。

### 1.3 控制类拦截 `backend/app/core/guard.py`（100 行）

**正则 denylist**，不是语义模型。命中高置信模式就返回统一拒绝话术 `REFUSAL`。

六类高置信模式（`_HIGH_CONFIDENCE`）：

| 模式 | 例子 |
|---|---|
| A 祈使前缀 + 控制动词 | 把李某的资质**改**到明年 |
| B 控制动词 + 完成标记 | 这瓶丙酮**报损掉** |
| C 控制动词 + 受控对象 | **删除**王某的**记录** |
| D 句首即控制动词 | **导出**名单 |
| E 直接写 SQL | 执行 UPDATE / DELETE |
| F 远程操作门禁 | 远程**把门打开** |

两个例外（避免误杀咨询）：

- `_PASSIVE`：被/已/是否… → "王某的授权**被撤销**了吗" 是在问状态
- `_ADVISORY`：怎么/流程/规定… 且**没有祈使前缀** → "报损需要什么流程"

> 定位说清楚：这是第一道便宜粗筛，原理上不完备。真正兜底是 **system prompt 第 5 条 + 只读 SQL 护栏 + 只读数据库账号**这三层。

### 1.4 日志脱敏 `backend/app/core/logging.py`（37 行）

`scrub(payload)` 递归遍历 dict/list，命中 `_MASK_KEYS`（name、emp_no、cert_no、quantity、witness_id、approver…）一律替换为 `***`。合规要求：日志不落盘姓名、工号、精确数量。

### 1.5 SQL 只读护栏 `backend/app/db/sql_guard.py`（166 行）

这是全项目最需要小心的文件。`validate_readonly(sql)` 的执行顺序：

```
1. 拒绝 MySQL 可执行注释 /*! ... */
2. 剥掉普通块注释与行注释
3. 把 %(name)s / %s 占位符临时替换成字面量 1（仅为解析）
4. sqlglot 解析（方言 mysql）
5. 必须是单条语句，且必须是 SELECT / UNION
6. AST 扫描：禁 DML 节点、禁危险函数(sleep/load_file/get_lock…)、禁 Lock(FOR UPDATE)、禁 information_schema 与 mysql 系统表、禁 INTO OUTFILE
7. 若最外层没有 LIMIT，则在**剥过注释的文本**后追加 LIMIT
8. 返回「原语句 + 补的 LIMIT」
```

**三个关键取舍**：

- 绝不用正则判写操作——`WHERE name='王 update'` 会被误杀
- 绝不返回 `ast.sql()`——那会把占位符吐成字面量，破坏参数绑定
- 必须剥注释后再补 LIMIT——否则 `SELECT ... -- 注释` 会让 `LIMIT 200` 落进注释里，等于没限制

### 1.6 连接池与取数入口 `backend/app/db/connection.py`（123 行）

`fetch_all()` 是**唯一**的数据读取入口，所有工具都走它，不允许自己开连接。内部两步：

1. `validate_readonly(sql)` 过护栏
2. 会话级加固：`SET SESSION TRANSACTION READ ONLY` + `SET SESSION MAX_EXECUTION_TIME=...`（云实例若禁止会话变量，降级为告警而不是中断）

另外提供 `ping()`（真实探活）、`describe_connection()`（返回实例版本、库名、账号、read_only，用于确认没连错环境）。

### 1.7 建索引 `backend/app/rag/ingest.py`（192 行）

两种切分策略，互不复用：

**`split_policy()` —— 规程/制度**
优先按「第 X 条」切；没有条款号的（"一、二、三"式制度）退回按 `##` 标题切。

**`split_sds()` —— SDS（安全关键）**
`sds/*.md` 用的是国标 16 项细分标题，但业务要求固定四段。这里用 `_SECTION_ALIAS` 做**标题 → 四段语义**的归并：

```
标识信息/成分组成 → 理化特性
危险性概述/急救措施/消防措施 → 危害
储存要求/操作处置与储存 → 储存
泄漏应急处理/废弃处置 → 应急处置
```

相邻同段合并（避免同一语义被标题拆碎），每段再按 800 字/100 重叠细分，metadata 记 `section` 与 `part`。

> 红线：`应急处置` 绝不能和 `储存` 落进同一个 chunk，否则"着火怎么灭"可能召回"储存温度"。

`build_index()` 先删旧集合再重建（避免重复执行导致 chunk 成倍累积），入库后打印四段分布。

### 1.8 检索 `backend/app/rag/retriever.py`（107 行）

```
建成/查询两侧都锁定 hnsw space = cosine
   ↓
asimilarity_search_with_relevance_scores(fetch_k=20)
   ↓ 最高分 < rag_score_threshold(0.30) → 直接返回空
amax_marginal_relevance_search(k=4, lambda_mult=0.5)
   ↓ MMR 失败
退回按相关度取前 k 条
```

三个细节：

- **必须用 cosine**：Chroma 默认 l2，高维 embedding 下相关度挤在 0.3 以上，阈值形同虚设，"查不到就说查不到"的兜底会失效
- 阈值不达标返回空列表，让模型回答"规程中未找到相关规定"，**不给编造的机会**
- Embeddings 必须 `check_embedding_ctx_length=False` + `chunk_size=10`，否则 DashScope 兼容模式报 400

### 1.9 工具层 `backend/app/tools/`（约 900 行，9 个工具）

**`__init__.py`（54 行）** —— 工具注册 + 防回归断言：工具名不能命中 `_FORBIDDEN_TOOL_NAMES`（update/delete/export/open_door…），且每个工具必须有 description（模型靠它路由）。有人加了写工具，**导入时就炸**。

**`policy_tools.py`（17 行）** —— `search_policy` 薄包装 `retrieve_policy` + `format_hits`。

**`access_tools.py`（361 行）** —— 全项目最核心。

| 组成 | 说明 |
|---|---|
| `_SQL_LAB` | 先查实验室是否存在，避免把"编号写错"报成"查无此人" |
| `_SQL_PERSON_GATES` | persons ⟕ qualifications ⟕ lab_authorizations ⟕ **labs**，一条 SQL 取齐三闸所需字段 |
| `_SQL_DAY_COMPANION` | 双人闸取证：只认「进 + 验证通过」，`MAX(companion_no)` 取当天最大值 |
| `_judge()` | 三闸判定，顺序固定 **资质 → 授权 → 双人**，任一不过即短路 |
| `check_lab_access()` | 装配层：解析时间 → 验实验室 → 查人 → 按 person_id 去重（换证会有多条）→ 逐人取证 → 输出 |
| `get_person_qualification()` | 按人分组输出全部证书（原实现只看第一行，同名会串） |
| `query_records()` | NL2SQL：拼 `DIALECT_PROMPT` + DDL 上下文 → 模型生成 SELECT → `fetch_all` 过护栏 → 转 markdown |

`_judge` 的两条铁律：

- **资质看 `expire_date` 不看 `status`**（库里存在"状态有效但已过期"的记录，王某就是）
- **双人闸 fail-closed**：当天查不到「进+通过」记录时判「需双人同行」，不放行

**`inventory_tools.py`（217 行）**

| 函数 | 要点 |
|---|---|
| `to_interval()` | 数量区间化：<5 "少量"，[5,50) 步长 5，[50,500) 步长 50，≥500 步长 500，下界不低于 5 |
| `masked_quantity()` | **唯一对外数量出口**：敏感类别走区间，其余给精确值 |
| `query_inventory()` | 精确名/CAS → 查不到则 LIKE 模糊，提示别名（"双氧水"=台账里的"过氧化氢"） |
| `reconcile_inventory()` | 台账/领用/制度**三查并行** `asyncio.gather`；有期初按"期初−领用"严格比，无期初按"领用超结存"周转比；超阈值判账物不符；额外统计缺见证人笔数 |

脱敏落在**工具返回值**，不靠提示词——如果返回精确数字，模型迟早会说出去。

**`equipment_tools.py`（263 行）**

- `query_equipment()`：条件全留空时提示至少给一个条件；用 `DATEDIFF(calibrate_due, CURDATE())` 直接算剩余天数
- `check_equipment_loan()`：查未归还记录 + 逾期天数 + 全部借还历史；维修中/报废/校准过期都明确标"不可借出"
- `list_calibration_due(days=30)`：过期与临期分两组，排除报废设备和 `calibrate_due` 为空的储存设施
- 共同铁律：**校准看 `calibrate_due` 不看 `status`**（同人员资质的坑）

### 1.10 Agent 编排 `backend/app/agent/`

**`prompts.py`（42 行）** —— system prompt 10 条硬规则，按优先级排：

1. 具体人/室/时间/化学品的事实必须查库
2. 规程类必须检索，查不到就说"未找到"，禁止编造条号
3. 准入必须调 `check_lab_access`，不许自己拼 SQL 判断
4. 账实核对必须三处都查
5. 控制类请求一律拒绝
6. 剧毒品数量只给区间
7. 设备问题必须查库，校准以有效期字段为准
8. 结尾注明 `[规程]` / `[数据]`
9. **不许自己推断"今天"是哪天**，`at_time` 留空即服务器时间
10. **工具返回的数值/区间/日期必须原样照抄**，不许换算改写

> 第 9、10 条是踩坑补的：模型曾把今天猜成 2024-04-05（导致资质判定反转），也把"不足 5 克"改写成"10–50 克"。

**`middleware.py`（15 行）** —— `ModelCallLimitMiddleware(run_limit=8)` + `ToolCallLimitMiddleware(run_limit=12)`，防止死循环烧钱。

**`graph.py`（180 行）** —— **v2.0 起按配置装配**：`get_agent(cfg)` 用 `(id, updated_at, 模型参数, prompt, tools)` 做指纹缓存，
配置一改下次请求自动重建；工具白名单经 `tools_for()` 在服务端过滤；system prompt 由
`compose_prompt()` 拼装（固定的 `SAFETY_PREFIX` + 用户补充，只读约束不可覆盖）。
会话上下文用 `InMemorySaver`（进程内存，只增不减），因此配套 `start_session_reaper()` 按 `SESSION_TTL_SECONDS` 定期 `adelete_thread` 释放。

**`agents/store.py`（约 300 行）** —— Agent 配置持久化。**存在 JSON 文件而非数据库**：MySQL 账号只有
`GRANT SELECT`，不为几条配置引入写账号。原子写（tmp → `os.replace`）+ 线程锁 + mtime 缓存失效。
首次启动自动写入 4 个内置 Agent；内置不可删除、只可停用。

### 1.11 API 层 `backend/app/api/`

**`chat.py`（84 行）**

- `POST /chat`：先 `detect_control_intent` → 命中直接返回 `refused: true`，**不进 Agent**（省一次模型调用）；否则 `ainvoke` 取最后一条消息
- `POST /chat/stream`：SSE。**只转发最终回答**——`meta["langgraph_node"]` 含 `tools` 的中间分块全部跳过，否则 SQL 和人员行踪流水会漏给前端；末尾发 `data: [DONE]`

**`health.py`（63 行）** —— 三个探针：`/health`（存活+MySQL）、`/health/detail`（实例版本/库名/账号/ssl/LLM key 是否设置，可安全贴工单）、`/health/ready`（MySQL 与 Key 都就绪才 200，否则 503）

**`agents.py`（约 130 行）** —— Agent 配置 CRUD：`GET /api/agents`、`GET/PUT/DELETE /api/agents/{id}`、
`POST /api/agents`、`POST /api/agents/{id}/status`。写操作只作用于配置文件，变更后 `invalidate_agent()`。

**`data.py`（313 行）** —— 管理控制台的数据接口，共 10 个：`/data/overview` 聚合 9 个数据集一次返回，另有 labs/persons/qualifications/authorizations/access-events/inventory/hazmat-uses/equipment/equipment-loans 单资源。
全部是**文件内常量 SQL**（不接受外部拼接），字段统一转 camelCase 对齐前端类型；库未就绪返回 503。
> 口径差异：工具层给模型看的是脱敏区间，这里给管理员看的是完整数字。

## 3. 一条问题从输入到回答

以"王某能不能进 3 号暂存间"为例：

| 步 | 位置 | 做什么 |
|---|---|---|
| 1 | `ChatPage.vue` | 前端判断 `VITE_API_MODE`，调 `streamChatFromBackend()` |
| 2 | `api/chat.py` | 先过 `detect_control_intent()`；本例不命中，进 Agent |
| 3 | `agent/graph.py` | `create_agent` 把问题 + 10 条规则 + 9 个工具描述发给 qwen-plus |
| 4 | 模型 | 读到"准入"语义 → 选择 `check_lab_access` 工具，`at_time` 留空 |
| 5 | `tools/access_tools.py` | 留空 → `datetime.now()`；查实验室 → 查三闸字段 → 按人分组 → 查当天门禁 |
| 6 | `db/connection.py` | 每条 SQL 先过 `validate_readonly()`，再在只读会话里执行 |
| 7 | `_judge()` | 资质闸：`expire_date` 早于今天 → 判「资质过期」，短路返回 |
| 8 | 模型 | 拿到工具文本，按第 10 条原样引用日期与证书号组织回答 |
| 9 | `api/chat.py` | SSE 逐段下发（跳过 tools 节点的中间内容），末尾 `[DONE]` |
| 10 | `ChatPage.vue` | 渲染流式文本，结束落库到会话 |
