## 二、第二轮优化内容（本次改动）

### 2.1 修掉的真实缺陷（均经实测复现）

| # | 缺陷 | 实测证据 | 修复 |
|---|---|---|---|
| 1 | **SQL 护栏可被可执行注释绕过** | `/*!50000 DELETE */ FROM persons` 被 sqlglot 判为 `Select`，护栏**放行**；MySQL 会真执行 DELETE | 识别 `/*!` 即拒绝（而非剥离——剥离会导致执行的 SQL 与分析的 SQL 不一致） |
| 2 | **尾注释吞掉 LIMIT 注入** | `SELECT ... -- 注释` 追加 ` LIMIT 200` 后，实测解析出的 LIMIT 为 `None`，全表扫描 | 追加 LIMIT 前先剥离注释 |
| 3 | **控制类拦截被情态词绕过** | 「能否把王某的门禁权限注销掉」因含"能否"被判为咨询而**放行** | 放行词表移除所有情态词，改为「控制意图优先、咨询作例外」 |
| 4 | **咨询误杀** | （修复 3 时需保留）「报损需要走什么流程」不能拒 | 用 how-to 例外 + 祈使前缀检测区分 |
| 5 | **核心里程碑字段被静默降级** | 1 字节截断，核心值变更被悄悄丢弃 | 是 4 的连带效应，见说明 |
| 6 | **DDL 路径硬编码容器路径** | `_load_ddl()` 写死 `/app/mysql/init/01_schema.sql`，本机/云库必崩 | `config.resolve_ddl_path()` 多候选探测 + `MYSQL_DDL_PATH` 可覆盖 |
| 7 | **检索阈值形同虚设** | 未指定 distance metric，langchain-chroma 按 l2 归一化，相关度无区分度 | 建索引与查询两侧显式锁定 `cosine` |
| 8 | **重名人员提示失效** | `get_person_qualification` 只看 `rows[0]`，同名多人的资质混在一人名下 | 按 `person_id` 分组输出，并给出重名警告 |
| 9 | **双人闸判定脆弱** | 取当天**第一条**门禁事件的 `companion_no`，不校验 `auth_result`/`direction`，顺序一变结论翻转 | 聚合当天「进 + 通过」事件取最大同行人数；查不到则 fail-closed |
| 10 | **资质多条时结论自相矛盾** | 同一人换证/复审产生多条记录，逐行判定会输出互相矛盾的结论 | 按 `person_id` 去重，只留 `expire_date` 最新一条 |
| 11 | **实验室编号写错答成"查无此人"** | 把运维问题（编号不存在）误报为数据问题 | `check_lab_access` 先单独校验 `lab_id` |
| 12 | **会话存储内存泄漏** | `InMemorySaver` 只增不减，`SESSION_TTL_SECONDS` 声明了却无人使用 | 接入 TTL 后台清理任务 |
| 13 | **DB 连不上则进程起不来** | `await init_pool()` 失败直接抛异常，容器反复重启看不到原因 | 启动降级，由 `/api/health` 暴露状态与错误类别 |
| 14 | **流式接口泄漏工具中间输出** | SSE 转发所有 chunk，SQL 与原始行踪流水会流向前端 | 按 `langgraph_node` 过滤掉 tools 节点的输出 |
| 15 | **索引重复入库** | `build_index` 每次 append，跑两次语料成倍累积 | 默认先删集合再重建 |
| 16 | **`information_schema` 子串误杀** | `dept='information_schema'` 这种字符串常量也被拒 | 改为按 AST 表标识符判断，不做子串匹配 |
| 17 | **敏感类台账差异泄漏精确值** | `reconcile_inventory` 的差值可由结存与领用反推精确库存 | 敏感类结存/领用/差值全部区间化 |

> 说明：上表 #5 是 #3 修复过程中的连带清理项，保留编号仅为与实测记录对齐。

### 2.2 云数据库接入（本次重点）

连接层针对云 MySQL 的三处关键差异做了适配：

| 差异 | 适配 |
|---|---|
| 首包握手慢（TLS + 公网往返） | `MYSQL_CONNECT_TIMEOUT` 默认放宽到 10s；`pool_recycle` 主动回收，避免拿到被云侧断开的死连接 |
| 云厂商普遍要求/建议 TLS | `MYSQL_SSL=true` 启用加密；需严格校验时给 `MYSQL_SSL_CA` 指向厂商 CA |
| 云托管实例可能限制会话变量 | `SET SESSION ...` 失败降级为告警，不再中断查询；语句超时由护栏的 8s 兜底 |

**新增连通性自检脚本** `backend/scripts/db_check.py`，按「网络 → TLS → 账号 → 权限 → 表」五层递进探测，哪层断了一目了然：

```bash
cd backend && python -m scripts.db_check
```

**新增健康检查接口**：

| 接口 | 用途 |
|---|---|
| `GET /api/health` | 存活 + MySQL 连通性（容器 healthcheck 用） |
| `GET /api/health/detail` | 连接详情：实际连到的实例版本、库名、账号、是否只读实例——**用来确认没连错环境** |
| `GET /api/health/ready` | 就绪探针，MySQL 与 LLM Key 都就绪才返 200，否则 503 |

## 六、启动路径

### 6.1 本机 MySQL（最快）

本机装 MySQL 8.0，把 `mysql/init/` 下脚本按文件名顺序执行：

```bash
mysql -u root -p < mysql/init/01_schema.sql
mysql -u root -p < mysql/init/02_readonly_user.sql
mysql -u root -p < mysql/init/03_seed.sql
```

仓库根目录的 `start.ps1` 会按 `.env` 的 `MYSQL_HOST`/`MYSQL_PORT` 探测端点，不可达时只提示不阻断（后端以 degraded 状态启动）。

### 6.2 云数据库（本次新增支持）

1. **云控制台准备**：实例已创建 → 建库 `lab_hazmat` → 确认账号有 `SELECT` 权限 → 安全组/白名单放行你的出口 IP。
2. **建表灌数据**：按 `mysql/init/` 顺序执行 `01_schema.sql` → `02_readonly_user.sql` → `03_seed.sql` → `04_labs.sql`。
   （若 `02` 里的只读账号密码与云平台要求不符，用云控制台的账号替代，并同步改 `MYSQL_USER`/`MYSQL_PASSWORD`。）
3. **配置 `.env`**：

```bash
cp .env.example .env
```

```ini
MYSQL_HOST=<云实例地址>          # 能用内网地址就用内网地址
MYSQL_PORT=3306
MYSQL_DB=lab_hazmat
MYSQL_USER=lab_readonly
MYSQL_PASSWORD=<真实密码>
MYSQL_SSL=true                  # 云厂商多要求加密
MYSQL_CONNECT_TIMEOUT=15        # 公网访问可放宽
MYSQL_DDL_PATH=                 # 留空自动探测，脚本不在仓库时才填
LLM_API_KEY=<真实 Key>
```

4. **先跑连通性自检**：

```bash
cd backend && python -m scripts.db_check
```

五层全部 `[OK]` 再启动后端。

### 6.3 启动后端

```bash
cd backend && uvicorn app.main:app --host 0.0.0.0 --port 8000
```

验证：

```bash
curl http://localhost:8000/api/health/detail
```

### 6.4 建向量索引

```bash
cd backend && python -m app.rag.ingest
```

会打印 chunk 数与 SDS 四段分布；重复执行会先删旧集合再重建。
