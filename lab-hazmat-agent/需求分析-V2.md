## 0. 本次修订：定位为什么必须拓宽

V1 的定位是**一个问题、一道闸**：某人某时能不能进某实验室。这个切口足够锋利，但它只覆盖了实验室安全治理的一个断面。

实际运行中暴露了三件事：

1. **事故与违规很少发生在"准入"这一环**。设备超期未校准仍在使用、试剂账物不符、借用设备长期不归还、人员资质过期但权限未撤——这些都不属于"能不能进门"，却都是真实风险点。
2. **V1 的数据底座已经"溢出"了原定位**。落地过程中陆续接入了人员、资质、授权、门禁、药剂台账、领用记录，之后又扩展了设备台账、借还记录、校准期、实验室学科分类与标准配置模板（共 12 张表）。**数据面早就不止危化品了**，需求文档还停在原地，会造成"文档说的和系统做的不是一回事"。
3. **用户问的问题天然是跨域的**。"3 号间那台液相色谱仪校准过期了，还在用的人有资质吗？"——一句话同时命中设备域、门禁域、人员域。V1 的单一域定位无法解释这种问题。

因此本次修订不改技术路线、不改只读底线，**只做定位升维与目标体系重构**。

### 定位演进对照

| 维度 | V1（REQ-LABHAZ-03） | V2（本文件） |
|---|---|---|

## 1. 背景与问题（拓宽后）

### 1.1 从"一道闸"到"一个体系"

实验室安全不是一道门的问题，是**五类要素同时成立**的问题：

```
人（人员）  资质是否在有效期、授权是否在范围、是否经培训
机（设备）  是否在检定校准期、是否被超期占用、保管人是否明确
料（物料）  存量与领用是否对得上、是否超量存放、是否混放禁忌
法（制度）  规程怎么规定的、条款在哪、处置流程是什么
环（环境）  谁能进、几人进、什么时段进、是否双人双锁
```

**五类要素分别记在五个系统/五本账里**，任何一处断裂，人工都很难自发发现。

### 1.2 五类典型断点

| # | 断点 | 现实表现 | V1 是否覆盖 |
|---|---|---|---|
| 1 | **人 × 环** | 资质过期但门禁权限未撤，人照样进得去 | ✅ 覆盖 |
| 2 | **料 × 料** | 台账剩 8 瓶、流水领了 12 瓶，两边分别看都正常 | ✅ 覆盖 |
| 3 | **机 × 机** | 设备状态"在用"，但校准期早已过期 | ✅ 已扩展覆盖 |
| 4 | **机 × 人** | 借出的设备逾期未还，保管人不知道 | ✅ 已扩展覆盖 |
| 5 | **法 × 全域** | 知道违规了，但说不出依据哪一条 | ✅ 覆盖 |

> 断点 3、4 是 V2 新增的核心场景。它们的共同特征与断点 1、2 完全一致：**单看每一份数据都"正常"，只有交叉比对才暴露问题**。这也是本平台真正的差异化能力——不是"能查"，而是"**能查出对不上的地方**"。

### 1.3 一句话问题定义

> 实验室治理的判定依据**一半在制度、一半在分散的台账**，而**最容易出问题的交叉校验目前完全靠人，且没人在做**。

V1 解决的是其中的准入交叉；V2 把它推广到**人员、设备、物料三个域的任意交叉**。

## 2. 项目定位

### 2.1 定位陈述

> **一个只读的实验室全要素治理助手**：把分散在人员、设备、物料、制度、门禁五个域的数据汇聚成可对话的知识底座，让安全员用一句自然语言完成"查事实、查依据、查矛盾"三件事。

### 2.2 三层价值

| 层 | 价值 | 典型问法 |
|---|---|---|
| **查得到** | 跨域事实检索，不用登五个系统 | "3 号间有哪些设备、谁保管、校准到什么时候" |
| **查得对** | 判定走固化逻辑与规程原文，不靠模型臆断 | "王某今天能进剧毒品间吗" |
| **查得出问题** | 主动交叉比对，输出风险清单 | "哪些人资质过期仍在进实验室" / "哪些设备校准过期还在用" |

> 第三层是平台存在的理由。前两层是必要基础，但**只有第三层能替人发现人发现不了的问题**。

### 2.3 与现有系统的关系

**不替代、不改造、不写入。** 平台是现有系统之上的**只读汇聚层与问答层**：

```
考试系统 ─┐
授权台账 ─┤
门禁系统 ─┼─→ 只读汇聚（MySQL 只读账号）─→ 交叉校验 ─→ 问答与预警
设备台账 ─┤                              ↑
药剂台账 ─┘                        规程/SDS 知识库
```

底层系统该谁管还谁管，平台只回答"现在是什么状态、有没有矛盾、按哪条处理"。

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 | 衡量方式 | 状态 |
|---|---|---|---|
| **G1** | 五域事实可查：人员、设备、物料、制度、门禁 | 每域至少 1 个专用工具，问答可命中 | ✅ |
| **G2** | 准入三闸判定同时校验资质、授权、双人 | 与人工核算逐条对齐，**100%** | ✅ |
| **G3** | 四类交叉校验：人×环、料×料、机×机、机×人 | 内置差异样本识别率 **≥ 90%** | ✅ |
| **G4** | 风险预警：资质到期、校准到期、借还逾期、账物不符 | 可列出待处理清单，按紧急度排序 | 🔄 部分（单点可查，未汇总） |
| **G5** | 制度与 SDS 可溯源 | 回答可定位到章节/小节，查不到如实说"未找到" | ✅ |
| **G6** | 敏感信息分级脱敏 | 剧毒品/易制爆精确数量区间化率 **100%** | ✅ |
| **G7** | 只读边界不可突破 | 控制类指令拒绝率 **100%** | ✅ |
| **G8** | 质量可回归 | 离线断言 ≥ 190 项全通过；评测集覆盖六类问题 | ✅ 192 项 |
| **G9** | 领域可扩展：新增要素不改架构 | 新增一个域 = 加表 + 加工具 + 加页面 | ✅ 设备域已验证 |
| **G10** | 多轮澄清：重名、别名、口径不明时追问而非猜测 | 重名返回候选并要求工号确认 | ✅ |

> G4 是 V2 的新增重点：目前四个交叉校验都是**按需查询**（用户问什么查什么），尚未做成**主动汇总的预警视图**。这是 V2 阶段最值得补的一块。

### 3.2 非目标

| 不做 | 为什么 |
|---|---|
| **改资质、改台账、报损、撤权、导名单、开门** | 只读平台，一律拒绝，引导走人工审批 |
| **替代门禁/台账/考试系统** | 平台是汇聚层，不是记录源头；改了源头就失去中立性 |
| 视频识别取用行为 | 只消费结构化记录，不做视觉识别 |
| 物联网柜门/温湿度实时控制 | 只读，不接管设备控制面 |
| 采购、报废、财务全生命周期 | 只覆盖"在用资产的状态与风险"，不覆盖资产财务 |
| SDS 全文问答 | 只做四段要点摘要，全文问答噪声大且切错的后果危险 |
| 自动处置 / 自动上报 | 只给"按第 X 条应如何处理"的建议，决定权在人 |
| 替人做合规结论（"这算重大隐患"） | 平台给事实与条款，定性由安全员判断 |

> 最后一条值得强调：**平台不做合规定性**。它能说"该设备校准已过期 47 天，仍在用，共 3 次借用记录"，但"这属于几级隐患、要不要停实验"必须由人依据制度判定。越界定性会让责任边界模糊。

## 4. 用户与场景

### 4.1 用户角色

| 角色 | 关心什么 | 典型问题 |
|---|---|---|
| 实验室安全员 | 有没有人违规进、有没有账物不符 | "上周进过 3 号间的人里谁资质过期了" |
| 实验室负责人 | 本室人员与设备是否合规 | "我们室哪台设备校准快到期了" |
| 院系安全管理员 | 跨实验室的整体风险 | "全院有哪些人合格证 30 天内到期" |
| 资产管理员 | 设备借还与闲置 | "哪些设备借出超过 30 天未还" |
| 实验人员（教师/研究生/本科生） | 自己能不能做、怎么做才合规 | "我要用丙酮做萃取，需要什么手续" |
| 安全督导 / 审计 | 依据在哪、是否可追溯 | "双人领用制度出自哪一条" |

### 4.2 典型场景（跨域）

| # | 场景 | 涉及域 |
|---|---|---|
| 1 | 我要用硝酸做消解，需要什么资质、在哪个柜取、剩多少 | 法 + 人 + 料 |
| 2 | 上周进 3 号间的人里，谁资质过期了，按制度该怎么处理 | 环 + 人 + 法 |
| 3 | 3 号柜丙酮台账 8 瓶、领用 12 瓶，对得上吗 | 料 + 料 + 法 |
| 4 | 剧毒品间谁单人进去过 | 环 + 人 |
| 5 | 哪些设备校准过期还在用，保管人是谁 | 机 + 人 |
| 6 | 张某借的仪器到期没还，借了什么、谁批的 | 机 + 人 |
| 7 | 化学实验室标配哪些设备，我们室缺什么 | 法（分类模板）+ 机 |
| 8 | 丙酮泄漏怎么处置（且不能混入储存要求） | 法（SDS） |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|

| 健壮 | 单条 SQL 失败不中断；**名称匹配失败必须明确告知，不得静默返回空** |
| 兼容 | 不修改门禁/台账/考试系统；只读消费 |
| 数据质量 | 化学品以 CAS 号为主键、名称辅助；设备以 `equip_id` 主键 |

## 7. 数据模型（12 张表，按域划分）

| 域 | 表 | 说明 |
|---|---|---|

| 人员 | `lab_authorizations` | 实验室授权，可随时撤销 |
| 环境 | `access_events` | 门禁通行流水，含同行人数 |
| 物料 | `hazmat_inventory` | 危化品台账，含精确结存（内部值） |
| 物料 | `hazmat_uses` | 领用记录，含见证人 |
| **设备** | `equipment` | 设备台账，**校准到期是判定关键** |
| **设备** | `equipment_loans` | 借还记录，含应还/实还时间 |
| **制度** | `lab_categories` | 学科方向分类（物理/化学/生物/材料/分析测试） |
| **制度** | `category_equipment` | 分类标配设备模板 |
| **制度** | `category_reagents` | 分类标配试剂模板 |

三处不可动摇的设计：

1. **资质与授权分表** —— 合格证是学校层面发的、有效期固定；导师授权是课题组层面、可随时撤销。合并会导致"查错类"。
2. **判定只看日期字段** —— 资质看 `expire_date`、校准看 `calibrate_due`。业务库 `status` 常未及时更新，这正是最普遍的实际情况。
3. **台账 `updated_at` 与领用 `use_time` 分列** —— 交叉校验必须能对齐时间窗，否则大量假阳性会让人不再相信这个功能。

## 8. 关键决策与权衡

| 决策点 | 选择 | 理由 |
|---|---|---|
| 定位：单域深挖 vs 多域汇聚 | **多域汇聚 + 交叉发现** | 真实问题天然跨域；单域无法解释"设备过期+人员资质"这类复合问法 |
| 角色：替代业务系统 vs 只读汇聚层 | **只读汇聚层** | 替源头就失去中立性，且改造存量系统成本远高于收益 |
| 判定：固化 SQL vs 模型生成 | **固化 SQL** | 漏一闸结论就反；模型只调用与解释，不拼判定 SQL |
| 护栏：正则 vs AST | **AST（sqlglot）** | 正则两头不讨好：误杀 `name='王 update'`，漏放 `/*!50000 DELETE */` |
| 脱敏：提示词 vs 工具返回值 | **工具返回值** | 工具给精确值，模型迟早会说出去 |
| SDS 切分：固定长度 vs 按小节 | **按小节硬隔离** | 切串会让人按错误措施处理泄漏——安全性要求 |
| 设备校准：看 status vs 看日期 | **看 `calibrate_due`** | 与人员资质同类陷阱：状态字段滞后 |
| 新域扩展：改架构 vs 加域 | **加表+加工具+加页面** | 设备域已验证该路径，编排与护栏零改动 |
| 预警：被动查 vs 主动推 | **先被动、后主动** | 主动推送需要明确责任人与通知渠道，先做清单 |
| 合规定性 | **平台不做定性** | 只给事实与条款，定性权在人，避免责任边界模糊 |

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **定位拓宽导致"什么都查一点，什么都查不准"** | **高** | 五域各自保留专用工具与固化判定；不用 NL2SQL 替代确定性逻辑 |
| **SDS 被硬切导致危险建议** | 高 | 按小节切 + 人工抽样验收 |
| **准入判定漏闸** | 高 | 固化成工具，三闸写死 + 边界单测 |
| **控制类请求被执行** | 高 | 三层拦截 + 5 条 `expect_refuse` 用例 |
| 台账与流水时间口径不一致 | 高（假阳性会摧毁信任） | 统一时间窗 + 清单测 |
| 设备校准状态字段滞后 | 中 | 判定一律看 `calibrate_due` |
| 剧毒品库存被完整输出 | 中（合规） | 工具层区间化 |
| **预警清单无人认领** | 中 | 预警必须绑定责任人（安全员/保管人），否则只是报表 |
| 化学品别名匹配失败 | 中 | CAS 主键 + 名称辅助；区分"查不到"与"匹配失败" |
| 人员重名 | 中 | 返回候选 + 工号确认 |
| 前置数据仍在纸质状态 | 高（工期） | 立项时如实告知，前置工作单独列项 |
| 平台被当成合规定性依据 | 中（责任风险） | 明确定位：只给事实与条款，不定性、不背书 |
| Agent 死循环烧钱 | 低 | 两个 Limit 中间件必须开 |
