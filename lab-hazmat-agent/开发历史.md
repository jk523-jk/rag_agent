## 二、技术栈与选型理由

| 层 | 选型 | 关键理由 |
|---|---|---|
| 接入 | FastAPI + SSE | 原生 async；SSE 增量渲染比 WebSocket 简单，单向推送够用 |
| 编排 | LangGraph `create_agent` | 工具选择即路由，不需要手写节点图；中间件做调用次数限流 |
| 检索 | Chroma + MMR + 相似度阈值 | 向量空间显式固定 cosine，阈值才有区分度；查不到宁可返回空也不编造 |
| 数据 | MySQL 8 只读账号 | 业务数据本身是结构化的，关系一致性比文档库重要 |
| SQL 护栏 | sqlglot 解析 AST | 正则会被 `/*!50000 DELETE */` 绕过，也会误杀 `name='王 update'` |
| 模型 | OpenAI 兼容协议（DashScope） | 换供应商只改 base_url，代码零改动 |

### 阶段 4｜2026-10-16 上午：依赖落地与离线验证，修 3 个真 Bug

依赖装入 `G:\Anaconda3\envs\agent`（Python 3.11.17）后，在不连 MySQL 的前提下做全量离线验证，**发现并修复 3 个实际缺陷**：

1. **SDS 切分失效（严重）**
   语料用国标 16 项细分标题（标识信息/危险性概述/急救措施/消防措施/储存要求/泄漏应急处理），而切分器只认「理化特性/危害/储存/应急处置」四个精确词 —— 结果每份 SDS **只切出「储存」1 段**，应急处置内容全被吞掉。
   修复：新增 `_SECTION_ALIAS` 映射，把细分标题归并到四段语义（急救/消防→危害，泄漏应急→应急处置），5 份 SDS 恢复四段齐全，**应急处置 0 混入储存**。

2. **管理制度只切 1 块**
   制度用「一、二、三」章节号，不含「第X条」，条款切分器直接失效。
   修复：`split_policy` 增加标题式切分兜底，从 1 块恢复到 6 块。

3. **配置必填字段导致测试失败**
   `llm_base_url` / `llm_api_key` / `mysql_password` 无默认值，缺 `.env` 时 `Field required` 直接抛异常。
   修复：补默认值，缺省可启动。

## 六、关键技术决策

1. **准入判定必须固化 SQL，不让模型生成**
   漏一闸结论就反，错一次可能是安全事故。模型只负责调用与解释，不负责拼 SQL。

2. **护栏用 AST 不用正则**
   正则两头不讨好：`name='王 update'` 会误杀，`/*!50000 DELETE */` 会漏放。

3. **脱敏落在工具返回值，不落在提示词**
   如果工具返回精确数字，模型迟早会说出来。区间化在 `masked_quantity()` 里做，提示词只是第二道。

4. **判定以日期字段为准，不信 status**
   人员资质看 `expire_date`、设备校准看 `calibrate_due`。业务库里 status 常常没及时更新，这正是最普遍的实际情况。

5. **SDS 按小节硬隔离，绝不固定长度硬切**
   切错了不是"答不准"，是可能让人按错误方式处理危险品。这是安全要求，不是质量问题。

6. **服务连不上数据库也要能起**
   否则容器反复重启，运维看不出根因。改为 health 报 `degraded` + 具体错误。

7. **控制类拦截宁漏勿错杀（预检层）**
   "资质过期了该怎么改状态"是咨询，不能拒；低置信问法交给 system prompt 判断，预检只拦高置信祈使句。

## 七、踩坑记录（按严重程度）

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | SDS 切分只出 1 段 | 应急处置内容全丢，可能导致危险建议 | 标题→四段语义映射 |
| 2 | `/*!50000 DELETE */` 绕过护栏 | 只读系统可被删表 | 检测到可执行注释直接拒绝 |
| 3 | 尾注释吞掉 LIMIT | 全表扫描风险 | 追加 LIMIT 前先剥注释 |
| 4 | 双人闸取"当天第一条"事件 | 顺序一变结论就翻转 | 聚合当天所有「进+通过」取最大同行数，无记录 fail-closed |
| 5 | 资质多条时逐行判定 | 同一人出现矛盾结论 | 每人只取 `expire_date` 最新一条 |
| 6 | 实验室不存在时报"查无此人" | 把运维问题说成数据问题 | 先单独校验实验室编号 |
| 7 | 同名多人取 `rows[0]` | 资质混到一个人名下 | 按 `person_id` 分组输出 |
| 8 | 管理制度切 1 块 | 检索命中率低 | 标题式切分兜底 |
| 9 | 配置必填字段无默认值 | 缺 `.env` 直接启动失败 | 补默认值 |
