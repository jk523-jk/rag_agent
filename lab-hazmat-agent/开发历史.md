## 二、技术栈与选型理由

| 层 | 选型 | 关键理由 |
|---|---|---|
| 接入 | FastAPI + SSE | 原生 async；SSE 增量渲染比 WebSocket 简单，单向推送够用 |
| 编排 | LangGraph `create_agent` | 工具选择即路由，不需要手写节点图；中间件做调用次数限流 |
| 检索 | Chroma + MMR + 相似度阈值 | 向量空间显式固定 cosine，阈值才有区分度；查不到宁可返回空也不编造 |
| 数据 | MySQL 8 只读账号 | 业务数据本身是结构化的，关系一致性比文档库重要 |
| SQL 护栏 | sqlglot 解析 AST | 正则会被 `/*!50000 DELETE */` 绕过，也会误杀 `name='王 update'` |
| 模型 | OpenAI 兼容协议（DashScope） | 换供应商只改 base_url，代码零改动 |

### 阶段 4｜2026-10-16 上午：依赖落地与离线验证，修 3 个真 Bug

依赖装入 `G:\Anaconda3\envs\agent`（Python 3.11.17）后，在不连 MySQL 的前提下做全量离线验证，**发现并修复 3 个实际缺陷**：

1. **SDS 切分失效（严重）**
   语料用国标 16 项细分标题（标识信息/危险性概述/急救措施/消防措施/储存要求/泄漏应急处理），而切分器只认「理化特性/危害/储存/应急处置」四个精确词 —— 结果每份 SDS **只切出「储存」1 段**，应急处置内容全被吞掉。
   修复：新增 `_SECTION_ALIAS` 映射，把细分标题归并到四段语义（急救/消防→危害，泄漏应急→应急处置），5 份 SDS 恢复四段齐全，**应急处置 0 混入储存**。

2. **管理制度只切 1 块**
   制度用「一、二、三」章节号，不含「第X条」，条款切分器直接失效。
   修复：`split_policy` 增加标题式切分兜底，从 1 块恢复到 6 块。

3. **配置必填字段导致测试失败**
   `llm_base_url` / `llm_api_key` / `mysql_password` 无默认值，缺 `.env` 时 `Field required` 直接抛异常。
   修复：补默认值，缺省可启动。

### 阶段 11｜2026-10-19：巡检工作流落地（后端重新做回工作流）

v2.0 下线了纯前端演示的工作流画布。这一天用**巡检任务**把工作流重新做回后端：不画图、不让模型规划流程，而是把散在四类交叉校验里的判定按固定顺序批量跑一遍，输出带证据、带责任人、带建议的风险清单。同日还修掉两处回答质量问题。

#### 11.1 定位：为什么是巡检，不是画布

判断依据不是"不需要流程"，而是**本项目没有可配置的流程空间**：

| 不能配置的东西 | 原因 |
|---|---|
| 三闸顺序（资质→授权→双人） | 顺序错了结论就反，`需求文档 §8` 明确要求固化 SQL |
| 校准看哪个字段 | 只能看 `calibrate_due`，看 `status` 会漏判 |
| 脱敏按哪个类别 | 剧毒品/易制爆区间化是红线 |

一个可配置的编排器，等于**允许用户配出一个错误的安全判定**。所以模板写死在代码里，可配置的只有参数（观察窗口、时间范围、预警天数）。

分四层落地：

```
api/workflows.py        参数校验 / audience 脱敏 / HTTP
      ↓
workflows/runner.py     统一 as_of 快照、并发、单检查隔离、落盘
      ↓
workflows/checks/*.py   纯函数 run(ctx) -> list[Finding]   ← 只依赖 fetch_all
      ↓
db/connection.fetch_all 唯一只读入口 + AST 护栏 + LIMIT 注入
```

三个决定性设计：

1. **没有大模型也能跑完** —— 当时 `LLM_API_KEY` 仍是占位符，问答与评测都跑不动，巡检是唯一能立刻出真数据的功能。
2. **不复制判定，只复用** —— 阈值读 `get_settings().loss_threshold_*`，脱敏走 `to_interval`，与工具层同源。
3. **不完整 ≠ 无风险** —— 任一检查失败转 `status=partial`，前端红色横幅，绝不渲染成"未发现异常"。

#### 11.4 当日修掉的三个真缺陷

**① 巡检因「读取历史」而整体崩溃（严重）**

现象：直连真库跑 `run_workflow`，在产出任何结果前就抛 `PermissionError: [WinError 5] ...\data\runs`。

根因：`_read_index()` 走 `_index_path()` → `_runs_dir()`，而 `_runs_dir()` 会 `mkdir`。于是"只想查一下历史"触发了建目录，目录不可写就把整次巡检带崩——**用户连判定结果都拿不到**。

修法：拆出纯读取的 `_read_index_from(directory)` 与 `load_report()`，读路径永不建目录；`save_report` 失败降级为 `log.error`（明确写"本次运行不在历史中"），不阻断返回。

**教训：读路径不该有副作用。这是纯单测发现不了的，只有真跑一次才暴露。**

**② 查询结果只显示「工号1的人员」**

现象：回答出现「工号1的人员于…进入LAB-3实验室」，读的人无法确认是谁。

根因：`query_records` 让模型自己生成 SQL，模型只 `SELECT person_id`，没有 JOIN `persons`。

修法双层：`DIALECT_PROMPT` 规则 7 要求带出 `姓名（工号）` 并声明"只输出工号视为不合格"；再加机械兜底 `_enrich_person_names()`，检测到 `person_id`/`keeper_id`/`witness_id` 列就批量补名插到 ID 列前，查不到标「未登记」，已有姓名不重复补。

验证：person_id 1 → 王某（T2023001）、4 → 张某（T2021001）、99 → 未登记。

**③ 回答复述取数过程**

现象：回答开头出现「我需要查询上周（即从今天往前推7天）所有进入过实验室的人员记录。由于您没有指定具体实验室，我将查询所有实验室的门禁通行记录。」

根因：`SAFETY_PREFIX` 的【输出要求】从没禁止复述准备过程。

修法双层：【输出要求】新增禁令并列举典型句式（留唯一例外：确实需要用户补条件时一句话说清）；再加 `_strip_process_preamble()` 剥掉开头连续的过程句。保守设计——只认段首 + 完整成句；剥空则回退原文；记 `low` 不触发重试。因流式路径结尾会发 `replace` 整体覆盖，**已显示的过程句也会被纠正**。

#### 11.5 当日的设计原则沉淀

**提示词管方向，机械层管底线。** ② 和 ③ 用了同一套打法：提示词先立规矩，再加一层不依赖模型自觉的机械兜底。模型不听话时，兜底仍然生效。

## 六、关键技术决策

1. **准入判定必须固化 SQL，不让模型生成**
   漏一闸结论就反，错一次可能是安全事故。模型只负责调用与解释，不负责拼 SQL。

2. **护栏用 AST 不用正则**
   正则两头不讨好：`name='王 update'` 会误杀，`/*!50000 DELETE */` 会漏放。

3. **脱敏落在工具返回值，不落在提示词**
   如果工具返回精确数字，模型迟早会说出来。区间化在 `masked_quantity()` 里做，提示词只是第二道。

4. **判定以日期字段为准，不信 status**
   人员资质看 `expire_date`、设备校准看 `calibrate_due`。业务库里 status 常常没及时更新，这正是最普遍的实际情况。

5. **SDS 按小节硬隔离，绝不固定长度硬切**
   切错了不是"答不准"，是可能让人按错误方式处理危险品。这是安全要求，不是质量问题。

6. **服务连不上数据库也要能起**
   否则容器反复重启，运维看不出根因。改为 health 报 `degraded` + 具体错误。

7. **控制类拦截宁漏勿错杀（预检层）**
   "资质过期了该怎么改状态"是咨询，不能拒；低置信问法交给 system prompt 判断，预检只拦高置信祈使句。

8. **工作流 = 巡检任务，不是画布**（2026-10-19）
   模板写死在代码里，可配置的只有参数（窗口、时间、预警天数）。可配置的编排等于允许用户配出错误的安全判定。

9. **时间用 `as_of` 传参，不用 `CURDATE()`**（2026-10-19）
   工具层用 `CURDATE()` 无法离线固定时间；巡检统一传 `%(as_of)s`，保证幂等可复现。

10. **单检查隔离，整体 partial**（2026-10-19）
    一条 SQL 挂了不该让整单白跑；但也不能让"没查到"被读成"没问题"。失败记 `error`、整单转 `partial`、前端红色横幅。

11. **留痕失败不阻断判定**（2026-10-19）
    判定结果比日志重要。`save_report` 失败只打 error，不 500。

12. **提示词管方向，机械层管底线**（2026-10-19）
    「工号1的人员」和「复述取数过程」都用了同一套打法：提示词先立规矩，再加一层不依赖模型自觉的机械兜底。模型不听话时，兜底仍然生效。

13. **读路径不允许有副作用**（2026-10-19）
    `_read_index_from` 不建目录。由「巡检因读取历史而整体崩溃」直接换来的教训。

## 七、踩坑记录（按严重程度）

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | SDS 切分只出 1 段 | 应急处置内容全丢，可能导致危险建议 | 标题→四段语义映射 |
| 2 | `/*!50000 DELETE */` 绕过护栏 | 只读系统可被删表 | 检测到可执行注释直接拒绝 |
| 3 | 尾注释吞掉 LIMIT | 全表扫描风险 | 追加 LIMIT 前先剥注释 |
| 4 | 双人闸取"当天第一条"事件 | 顺序一变结论就翻转 | 聚合当天所有「进+通过」取最大同行数，无记录 fail-closed |
| 5 | 资质多条时逐行判定 | 同一人出现矛盾结论 | 每人只取 `expire_date` 最新一条 |
| 6 | 实验室不存在时报"查无此人" | 把运维问题说成数据问题 | 先单独校验实验室编号 |
| 7 | 同名多人取 `rows[0]` | 资质混到一个人名下 | 按 `person_id` 分组输出 |
| 8 | 管理制度切 1 块 | 检索命中率低 | 标题式切分兜底 |
| 9 | 配置必填字段无默认值 | 缺 `.env` 直接启动失败 | 补默认值 |
| 10 | DDL 路径硬编码容器路径 | 本机/云端 `FileNotFoundError` | `resolve_ddl_path()` 多候选探测 |
| 11 | 巡检因读取历史而整体崩溃（2026-10-19） | 用户连判定结果都拿不到 | 读路径拆出 `_read_index_from`，永不建目录；写失败降级为日志 |
| 12 | 查询结果只显示「工号1的人员」（2026-10-19） | 读的人无法确认是谁 | 提示词要求 JOIN `persons` + `_enrich_person_names()` 机械补名 |
| 13 | 回答复述取数过程（2026-10-19） | 用户看到的是工作计划不是答案 | 【输出要求】禁令 + `_strip_process_preamble()` 剥段首过程句 |
